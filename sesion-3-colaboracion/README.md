# Sesión 3: Colaboración real en GitHub

**Objetivo:** al terminar la sesión trabajas en equipo sobre un mismo repositorio con el flujo que se usa en proyectos reales: issue, rama, commit, pull request, revisión y merge.

## Qué vas a ver
- Cómo se organiza un equipo en GitHub: issues y pull requests.
- Revisar el trabajo de un compañero antes de que entre a `main`.
- Por qué `main` está protegida y no se puede cambiar sin revisión.
- Qué hacer cuando GitHub rechaza tu `push`: `git pull --rebase`.
- Qué es un fork y cuándo se usa.

## Qué necesitas
- Tu cuenta de GitHub y tu nombre de usuario: lo vas a anotar en la lista para que te inviten al repo de tu equipo.
- Tu celular a la mano, por si tu cuenta pide verificación en dos pasos (2FA).

## Mini-proyecto
Cada equipo arma un glosario de Git en el repo de su equipo. El contenido es sencillo a propósito: lo importante hoy es el flujo para trabajar en equipo. El archivo con el que empieza está en [mini-proyecto](mini-proyecto).
